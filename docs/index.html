How the dashboard works

Filter: Closed Opportunity · With Partner Tagged · Stage: 08 - Closed · Excludes Startup Program Partner

1 Does the closed Opportunity have a Partner tagged?

Start with Opportunities whose Stage is exactly 08 - Closed. Check whether the closed Opportunity has a tagged Partner.

Partner is tagged → Continue

Use the tagged Partner for this process. Exclude the Opportunity if its Partner Type is Startup Program Partner or its tagged Partner is AWS Marketplace.

No Partner → Stop

Skip this Opportunity. It does not appear in the worklist.

Salesforce field: the lookup labeled “Partner” is Referring_Partner__c.

2 Choose the Partner Sales Rep

PSE already populated → Use existing rep

Keep the existing PSE unless an explicit assignment review confirms a different active PSE. Mismatched assignments require review. Inactive PSEs require an RVP-confirmed active covering PSE and the Coverage role.

PSE blank → Use the Partner’s Owner

When you click Update, populate Partner_Sales_Rep__c with the Owner of the tagged Partner.

Key rule: Blank PSE fields use the active Partner Owner. A populated PSE changes only after an explicit assignment review. Both paths continue to Team and Split checks.

Using the dashboard

The list shows closed Partner Opportunities with missing PSE fields, missing Team or Split memberships, incorrect roles, or assignments requiring review. When the PSE field is blank, these checks use the tagged Partner’s Owner.

Refresh

Click Refresh to pull the latest data from Salesforce. The dashboard updates its counts and list based on the current Opportunity, Partner, PSE, Team, and Split records in SFDC. Data refreshes only when this button is clicked. Opening or reloading the page shows the last saved data.

Clickable boxes

Click a box to filter the list by category:

  1. Partner Opps with the Correct PSE Tagged: The tagged PSE and Partner Owner are the same user, but a field, membership or role still needs updating.
  2. Partner Opps with No PSE Tagged: The PSE field is blank. Use the active Partner Owner, then check Team and Splits.
  3. Partner Opps | Tagged PSE and Partner Owner is different: The two users differ. Confirm the assignment before updating. An inactive PSE requires an RVP-approved active covering PSE and the Coverage role.
  4. All Opps to update: All categories, including records that need review or have missing information.

What “missing” means: If the rep is already on the Team but has no Split, the Opportunity stays in the list. The same applies if the rep has a Split but is missing from the Team. The Opportunity remains until the PSE field, required roles and memberships are correct. Review, inactive and blocked records stay visible but are excluded from bulk updates.

Search and filters

Search by Opportunity name, Opportunity ID, or Account name. Use the filters below to narrow the selected category. You can select multiple values in each filter; selections across different filters work together. Clear a filter’s selections to remove that restriction.

Fiscal Quarter–Year
Filters by Opportunity Close Date using Zendesk’s fiscal calendar: Q1 Feb–Apr, Q2 May–Jul, Q3 Aug–Oct, and Q4 Nov–Jan. For example, November 2026 through January 2027 is FY2027 Q4.
Month
Filters by Opportunity Close Date. Month choices follow the selected fiscal quarters. For example, FY2027 Q4 shows November 2026, December 2026, and January 2027. Select multiple months if needed; changing quarters clears unavailable month selections.
Opportunity Type
Choose any Opportunity Types present in the current data; there is no fixed Type restriction.
Market Segment
Filters by the Opportunity’s Account Owner Market Segment.
Region
Filters by the tagged Partner’s Region (Referring_Partner__r.Region__c).
PSE Status
Choose Active, Inactive, or both. If a PSE is tagged, this is that user’s status. If the PSE field is blank, this is the Partner Owner’s status.

All counts use unique Opportunity IDs. The box counts reflect your search and filters. Use All Opps, Need RVP confirmation, or Ready to update to filter the list further. Their counts use the current category and other filters before that readiness selection. The matching-PSE, different-PSE, and no-PSE categories are separate. User IDs determine whether the PSE matches the Partner Account Owner; older exports use names until fresh data is exported. Records without enough information to compare stay visible in All Opps to update.

Update and export

Update in Salesforce applies the process to one Opportunity after confirmation. Update all ready — N in Salesforce applies it only to ready records across all filtered pages. Records needing review, RVP confirmation or missing information are skipped. Export CSV downloads that same filtered list.

Refresh only reads Salesforce. Update actions preserve an existing PSE, populate a blank PSE from the tagged Partner’s Owner, and add missing Team and Split entries. Each Opportunity uses its current or explicitly reviewed PSE. Blank or different roles are corrected; existing access levels, split types, and percentages are preserved; Salesforce errors are reported so you can retry the remaining steps.

Scope: Commissionable Opportunities at Stage 08 - Closed, with a Partner tagged, across all Opportunity Types. Excludes Opportunity Partner_Type__c = Startup Program Partner and tagged Partner AWS Marketplace. The Region filter uses the tagged Partner’s Region. No automatic Close Date restriction applies.
